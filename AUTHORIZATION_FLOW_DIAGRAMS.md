```

? /books/*    ?   ? 401     ?   ? 200      ?   ? 200       ?

Legend:
? 200 = Request allowed
? 401 = Unauthorized (no token or invalid token)
? 403 = Forbidden (authenticated but insufficient permissions)
```

## ?? Token Structure

### **User Token**
```
Header:
{
  "alg": "HS256",
  "typ": "JWT"
}

Payload:
{
  "sub": "user-guid",
  "email": "user@test.com",
  "jti": "unique-token-id",
  "http://schemas.microsoft.com/ws/2008/06/identity/claims/role": "User",
  "nameid": "user-guid",
  "name": "user@test.com",
  "exp": 1705421400,
  "iss": "https://tu-api.com",
  "aud": "https://tu-api.com"
}

Signature: HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)
```

### **Admin Token**
```
Payload (different role claim):
{
  "sub": "admin-guid",
  "email": "admin@fake.com",
  "jti": "unique-token-id",
  "http://schemas.microsoft.com/ws/2008/06/identity/claims/role": "Admin",  ? Key difference
  "nameid": "admin-guid",
  "name": "admin@fake.com",
  "exp": 1705421400,
  "iss": "https://tu-api.com",
  "aud": "https://tu-api.com"
}
```

## ?? Key Points

1. **Authentication** = "Who are you?" ? JWT token validation
2. **Authorization** = "What can you do?" ? Role checking
3. **401 Unauthorized** = Authentication failed (no/invalid token)
4. **403 Forbidden** = Authorization failed (valid token, wrong role)
5. **Repositories don't change** = Authorization is controller-level only
6. **Role claims in JWT** = Checked automatically by ASP.NET Core
7. **Seeding is idempotent** = Safe to run multiple times
